# Velg ut numeriske kolonner som gir mening å plotte over tid
numeric_cols = ['filling_degree', 'capacity_twh', 'filling_twh', 'filling_degree_prev_week', 'change_filling_degree']

fig, axes = plt.subplots(len(numeric_cols), 1, figsize=(10, 12), sharex=True)

for ax, col in zip(axes, numeric_cols):
    ax.plot(df['date'], df[col], label=col, color='tab:blue')
    ax.set_title(f'Time Series: {col.replace("_", " ").title()}')
    ax.set_ylabel('Value')
    ax.grid(True, linestyle='--', alpha=0.5)

axes[-1].set_xlabel('Date')
plt.tight_layout()
plt.show()

fig, ax1 = plt.subplots(figsize=(12, 6))

# Aksesystem 1: Fyllingsgrad (0 til 1 scale)
color = 'tab:blue'
ax1.set_xlabel('Date')
ax1.set_ylabel('Filling Degree (Ratio)', color=color)
line1 = ax1.plot(df['date'], df['filling_degree'], color=color, label='Filling Degree')
ax1.tick_params(axis='y', labelcolor=color)

# Aksesystem 2: TWh (Større skala)
ax2 = ax1.twinx()  
color = 'tab:orange'
ax2.set_ylabel('Filling / Capacity (TWh)', color=color)
line2 = ax2.plot(df['date'], df['filling_twh'], color=color, label='Filling (TWh)')
line3 = ax2.plot(df['date'], df['capacity_twh'], color='tab:green', linestyle='--', label='Capacity (TWh)')
ax2.tick_params(axis='y', labelcolor=color)

# Kombiner forklaringsskilt (legend) fra begge akser
lines = line1 + line2 + line3
labels = [l.get_label() for l in lines]
ax1.legend(lines, labels, loc='upper left')

plt.title('Reservoir Data: Combined View with Dual Y-Axes')
plt.grid(True, linestyle='--', alpha=0.3)
plt.tight_layout()
plt.show()

The first phase of the IND320 project focused on setting up a reproducible development environment and creating an initial data analysis pipeline for the residential unit dataset. The primary goal was to establish a seamlessly integrated workflow spanning local development in Jupyter Notebook, version control via GitHub, and live web deployment through Streamlit.

The work commenced with setting up the project infrastructure. A dedicated public GitHub repository was created to serve as the core codebase and version control hub. Subsequently, a Streamlit account was linked to the GitHub repository to enable continuous deployment. A minimal working Streamlit application was created, committed, and deployed to ensure the hosting pipeline was fully functional before integrating complex data logic. Once the deployment pipeline was established, the focus shifted to local data processing and exploratory data analysis (EDA) within Jupyter Notebook. The dataset, containing time-series observations relevant to the residential unit, was loaded using Pandas with automatic datetime index parsing. Initial data verification involved examining dataset metadata, column data types, missing values, and descriptive statistics using methods such as .info() and .describe().T. This ensured the overall data quality before generating visualizations.

Data visualization was carried out in two main steps. First, each parameter within the dataset was plotted individually across time. This single-variable approach made it easier to identify individual signal behavior, missing intervals, and general time trends across environmental or energy-related metrics. Second, combined time-series plots were developed using Matplotlib with dual/split Y-axes (twinx()). Combining variables with different scales on a unified time axis allowed for direct visual comparison between key parameters (such as comparing outdoor weather variables against indoor environment or energy metrics).

Finally, documentation was integrated directly into the notebook. Clear Markdown headings, explanatory comments for code blocks, a summary of AI tool usage, and a detailed project log were added to ensure full transparency and reproducibility. Overall, Part 1 successfully established both the technical infrastructure and the baseline analytical insights needed for subsequent project assignments.
